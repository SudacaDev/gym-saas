## Por qué requiere revisión

- Es una migración de schema (`CREATE TYPE`, `CREATE TABLE`, `ALTER TABLE ... FORCE ROW LEVEL SECURITY`) contra la base de datos de producción/real del proyecto, no una de prueba/local descartable.
- `scripts/apply-policies.ts` reaplica `0001`/`0002`/`0003` completos cada vez — son idempotentes por diseño, pero significa que este paso también re-toca RLS de las 6 tablas existentes, no solo la tabla nueva.
- No hay entorno de staging separado en este proyecto (un solo `DATABASE_URL`/`DATABASE_TRUSTED_URL` en `.env.local`) — este es el único lugar donde se puede aplicar.

## SQL que se aplicaría (`db/migrations/0004_nappy_mattie_franklin.sql`)

```sql
CREATE TYPE "public"."day_of_week" AS ENUM('monday', 'tuesday', 'wednesday', 'thursday', 'friday', 'saturday', 'sunday');
CREATE TABLE "class_schedules" (
	"id" uuid PRIMARY KEY DEFAULT gen_random_uuid() NOT NULL,
	"tenant_id" uuid NOT NULL,
	"day_of_week" "day_of_week" NOT NULL,
	"start_time" time NOT NULL,
	"end_time" time NOT NULL,
	"activity_name" text NOT NULL,
	"created_at" timestamp with time zone DEFAULT now() NOT NULL,
	"updated_at" timestamp with time zone DEFAULT now() NOT NULL
);
ALTER TABLE "class_schedules" ADD CONSTRAINT "class_schedules_tenant_id_tenants_id_fk" FOREIGN KEY ("tenant_id") REFERENCES "public"."tenants"("id") ON DELETE cascade ON UPDATE no action;
```
