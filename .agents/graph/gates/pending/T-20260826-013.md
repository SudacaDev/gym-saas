## Qué se hizo

Schema nuevo:
- `leads` (`tenant_id` + RLS estándar, `name`, `whatsapp`, `note` opcional, `status` enum, `created_at`/`updated_at`). `created_at` hace de "fecha" — no se agregó una columna de fecha separada, mismo criterio que `walk_in_sales`/`checkins`.
- `lead_status` enum (`nuevo`/`convertido`/`perdido`), default `nuevo` en creación — nunca elegible por el cliente en el POST.
- RLS estándar (`db/policies/0010_leads_rls.sql`), mismo patrón `tenant_isolation` que el resto de las tablas.

API nueva:
- `GET /api/v1/leads` (owner+staff, orden por `created_at` descendente).
- `POST /api/v1/leads` (owner+staff, crea con `status: "nuevo"` siempre).
- `PATCH /api/v1/leads/[id]` (owner+staff, solo cambia `status` — sin edición de nombre/whatsapp/nota en esta primera vuelta).

UI: pantalla nueva "Prospectos" (`/leads`, link agregado al nav para owner y staff, ícono `UserPlusIcon`) — tabla con nombre, WhatsApp (con link `wa.me/<dígitos>` para que el humano escriba manualmente, **no es un envío automático**), nota, fecha, `StatusPill` de estado, y botones "Convertido"/"Perdido" por fila (ocultos si ya está en ese estado). Diálogo "Nuevo prospecto" (nombre + WhatsApp obligatorios, nota opcional) mirando `ProductFormDialog` como plantilla.

**`npm run db:generate` corrido — la migración `db/migrations/0016_soft_ender_wiggin.sql` está generada y revisada, pero `npm run db:migrate` NO se corrió contra la base real.**

## Por qué requiere revisión (síncrona, no async)

- Tabla nueva + migración — mismo criterio `high` que toda migración anterior de este proyecto (T-011, T-012). Aplicar contra la base real necesita aprobación explícita antes de `npm run db:migrate`.
- Ver la sección de coordinación arriba: esta migración no es exclusiva de esta tarea, aprobarla aplica también el schema de T-010.
- Decisión de scope propia: el PATCH de estado es la única forma de editar un lead después de creado — no hay edición de nombre/WhatsApp/nota ni DELETE. Un lead "perdido" no se borra, queda como registro (mismo criterio "estado como soft-delete" que el resto del proyecto). No se pidió edición completa; agregarla habría sido sobre-alcance.
- Sin automatizaciones de seguimiento (WhatsApp/email) — explícitamente fuera de alcance, ya anotado aparte en el backlog grande de recordatorios/automatizaciones. El link `wa.me` en la tabla es solo un atajo de UI para que el humano escriba a mano, no dispara nada server-side.
