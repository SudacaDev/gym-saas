# Gate: T-20260826-006 — `staff` puede acceder al área `(owner)` (dashboard, socios, planes, horarios, check-in)

- severity: medium (`edit_non_prod_file`)
- approval_mode: async
- created: 2026-08-26

## Qué se hizo

`app/(owner)/layout.tsx`: `requireRole(context, ["owner"])` → `requireRole(context, ["owner", "staff"])`. Docstring actualizado — ya no describe el área como "owner-only"; explica que las restricciones finas (pricing de planes, roster de staff) se aplican por operación en cada API route, no en este guard.

## Por qué requiere revisión

- **Es un cambio de autorización, no un cambio visual** — a diferencia de T-20260826-004/005 (skeletons), esto decide quién puede entrar a toda un área del producto (dashboard, socios, planes, horarios, check-in). Se clasifica igual `medium`/`edit_non_prod_file` porque es 100% código reversible (un `git revert`), no toca datos ni cuentas reales, y las restricciones de negocio reales (quién puede fijar precios, quién ve el roster de personal) siguen viviendo — sin cambios — en cada API route.
- **No es una decisión nueva, es corregir una inconsistencia ya documentada:** el guard decía explícitamente en su comentario original "/dashboard below is owner-only... out of scope for this phase" — una decisión deliberada en su momento. Pero quedó desactualizada por trabajo de sesiones posteriores que ya asumían lo contrario: `owner-nav.tsx` (`ownerOnly: false` en Dashboard/Socios/Planes/Horarios/Check-in), `dashboard-page/index.tsx` (T-20260821-006, oculta ingresos solo para staff — sin sentido si staff no entra), y los API routes de `members`/`checkins`/`checkins/self`/`plans` (GET) ya en `requireRole(["owner","staff"])`. Este gate es la primera vez que el guard del layout se pone al día con esas tres señales.
- Verificado antes de aplicar (no asumido): `members`, `checkins`, `checkins/self`, `plans` (GET) → `["owner","staff"]`. Excepciones owner-only confirmadas y sin tocar: `plans` (POST, "pricing is the owner's call, not front desk's") y `GET /api/v1/staff` (roster, T-20260825-001) — ambas siguen bloqueando a `staff` a nivel API pase lo que pase con este layout, y `owner-nav.tsx` ya oculta el link "Equipo" (`ownerOnly: true`) así que `staff` ni lo ve en la navegación.
